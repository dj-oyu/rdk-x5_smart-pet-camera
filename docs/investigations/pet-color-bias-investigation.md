# Pet Color Classification Bias Investigation

Investigation date: 2026-05-13
Device: AI Pyramid Pro (AX8850 / AX650C)
Component: `src/streaming_server/internal/webmonitor/pet_color.go`
Classifier: `classifyPetColor()` — UV chrominance heuristic for mike / chatora / other

## Symptom

DB and filesystem distributions are heavily skewed toward `mike`:

| pet_id | filesystem | DB |
|---|---|---|
| mike | 1776 (74%) | 1750 |
| chatora | 391 (16%) | 388 |
| other | 262 (11%) | 292 |
| (no suffix) | 15 | 12 |

Sample period: photos captured 2026-03-20 .. 2026-05-13.
Ratio mike : chatora ≈ **4.5 : 1**.

Whether this reflects real activity ratio or classifier bias has not been
ground-truthed yet.

## How identity is decided

pet-album does **not** classify. It reads the `_<pet>` suffix from the
filename produced upstream:

- `src/ai-pyramid/src/ingest/filename.rs:31-40` `parse_comic_filename()`
  accepts `mike` / `chatora` / `other`, rejects anything else.
- The filename is generated by the rdk-x5 streaming server when a comic is
  emitted; the suffix comes from `dominantPetID()` over the panels'
  per-panel `petClass` votes.

Source of `petClass` per panel:
- `src/streaming_server/internal/webmonitor/pet_color.go:43`
  `classifyPetColor(nv12, w, h, bbox) PetColorResult`
- Inputs: NV12 frame + YOLO bounding box.
- Output: `{PetID, Confidence, Scatter, MeanU, MeanV, MeanY, UVDist, NumSamples}`.

## Algorithm summary

1. Clamp & area-gate bbox (`minBBoxArea = 2000`, ~45×45 px).
2. Sample Y plane (stride 4) → `meanY` (used for night/IR attenuation).
3. Sample UV plane (stride 2, aligned) → `samples`.
4. 16×16 UV histogram, drop bins with <2% of samples → `filtered`
   (background removal).
5. From `filtered`: compute `meanU`, `meanV`, `stdU`, `stdV`.
   - `scatter = stdU + stdV` — multi-color fur ⇒ high scatter.
   - `uvDist  = ||(meanU, meanV) − (orangeRefU=110, orangeRefV=155)||₂`.
6. Dual-feature classification (`pet_color.go:182-197`):

   | Branch | Condition | Result |
   |---|---|---|
   | confident mike | `scatter > 5.5 && uvDist > 15.0` | `mike`, conf ∈ [0, 1] |
   | confident chatora | `scatter < 4.5 && uvDist < 25.0` | `chatora`, conf ∈ [0, 1] |
   | ambiguous fallback | (else) | `scatter > 5.0 ? mike : chatora`, conf = 0.3 |

7. Night attenuation: if `meanY < 60`, multiply confidence by `meanY / 60`.

Aggregation across 4 comic panels: `dominantPetID()` sums confidence per
class; if best total < `minConfThresh = 0.5`, the whole comic becomes
`other`.

## Identified problem points

### 1. Asymmetric distance thresholds

```go
uvDistClose = 15.0   // chatora: within radius 15 of orange ref
uvDistFar   = 25.0   // mike:    outside radius 25 of orange ref
```

The chatora-confident zone is a small disk of radius 15; the mike-confident
zone is everything outside radius 25. Anything in the **annulus 15 ≤ uvDist
≤ 25** falls into the ambiguous branch even if the panel is genuinely a
chatora that happens to be lit slightly off-orange.

Geometrically the mike-confident region is much larger, so any panel whose
UV mean drifts (lighting, shadow, partial body coverage) is more likely to
land in mike-confident territory than in chatora-confident.

### 2. Ambiguous-zone tiebreak hard-codes a low scatter threshold

```go
default:
    if scatter > 5.0 { petID = "mike" } else { petID = "chatora" }
    confidence = 0.3
```

The trigger for confident mike is `scatter > 5.5`, but the ambiguous
fallback tips to mike at `scatter > 5.0`. So the band `5.0 < scatter < 5.5`
is automatically labeled mike with 0.3 confidence even though it never met
the confident-mike condition. The chatora confident threshold is `scatter
< 4.5`, so the band `4.5 < scatter < 5.0` is the only zone that defaults
to chatora — a much smaller scatter window than the corresponding mike
default.

### 3. Single reference point (orange) only

The UV-distance feature only measures "how close to chatora's orange." There
is no anchor for mike — mike is defined as "not chatora and noisy enough."
This means *any* cat that is not orange (white, gray, dark, tabby with low
UV scatter) tends to be pushed into the mike branch by default.

Concretely a black-furred or low-light cat with low UV variance is more
likely to land at `scatter ∈ [4.5, 5.5]` and either confident-mike fail
(needs `uvDist > 15` too — likely true since not orange) or default-mike
(scatter > 5.0). Without a positive mike anchor in UV space, the classifier
cannot detect "this is *also* not mike."

### 4. Confidence floor of 0.3 for the ambiguous branch is non-trivial

`dominantPetID` requires aggregate score ≥ `minConfThresh = 0.5` over 4
panels. With per-panel ambiguous confidence 0.3:
- 2 ambiguous panels voting the same way → 0.6 → passes threshold.
- The aggregation therefore promotes ambiguous-zone votes to comic-level
  classifications easily, propagating the asymmetric bias from items 1-2
  into the final pet_id assignment.

### 5. Calibration provenance is undocumented

`pet_color.go:27-36` constants (`scatterHigh/Low`, `uvDistClose/Far`,
`orangeRefU/V`) carry a comment "initial values — calibrate from production
logging" but there is no record of whether they have been recalibrated
against ground-truth labels.

The `[PetColor]` log line (`pet_color.go:215`) records all features per
detection, so a calibration dataset can be assembled retroactively, but
there is no script or notebook in-tree that does this analysis.

### 6. Night attenuation only affects confidence, not the decision

```go
if meanY < nightYThresh { confidence *= meanY / nightYThresh }
```

At night/IR (`meanY < 60`) UV becomes unreliable. Confidence is reduced
proportionally, but the `petID` itself is still produced by the daytime
thresholds. A low-light frame that lands in the mike-confident branch
geometrically will still vote for mike — just with a small weight. Across
many night frames the bias can still accumulate via `dominantPetID`'s
summation.

It is unclear from the code whether night frames should instead skip
classification entirely (e.g. return `"other"` when `meanY < nightYThresh`).

### 7. No regression coverage for the bias-prone regions

`pet_color_test.go` covers the canonical `testdata/mike.jpg` and
`testdata/chatora.jpg`, but there are no test cases for:
- panels in the UV annulus 15 ≤ uvDist ≤ 25
- panels with scatter ∈ [4.5, 5.5]
- low-light (meanY < 60) panels
- panels where the cat occupies a small fraction of the bbox (background
  contamination)

So any threshold tweak risks silently regressing on these conditions.

## Data not yet collected

- Ground-truth labels for a meaningful sample of the 2,429 captured
  photos. Without this the bias magnitude cannot be quantified separately
  from real activity skew.
- Feature distribution histograms (scatter, uvDist, meanY) per
  ground-truth class. Needed to choose new thresholds defensibly.
- Per-pet activity prior from the litter box / feeder timestamps (if any
  exist) as an independent estimate of the true mike : chatora ratio.
